# Spec: host capability detection (hw)

Boot-time detection of what this host's ffmpeg and GPUs can do: the single source of `GET /v1/capabilities` and of the `HostCaps` the decision (`decide.md` section 11) reads. Pure logic: `crates/core/src/hw`; IO: `crates/engine/src/hw`. Golden vectors: `fixtures/hw/*.json` (generated by the host harness `backend/test/engine-vectors/hw-vectors.spec.ts`). Tags are relative to the root of `fliks` (`backend/src/modules/streaming/transcoding` abbreviated `T/`).

## 0. Contract

- `GET /v1/capabilities` -> `Capabilities`; `POST /v1/decide` without `hostCaps` reads `HostCaps` of the same snapshot. `[new]`
- 503 + `Retry-After: 1` on both until the first detection run ends. A re-run (section 7) keeps serving the previous snapshot. `[new]` (TS: encoders read "usable" and probes false until the boot probe lands, `T/codec/encoder-probe.ts:34-37`; the engine fails closed instead of deciding on a half-known host.)
- The binary is `FFMPEG_PATH` or `ffmpeg` on `PATH`. `[new]` (TS: `execFile('ffmpeg')`, PATH only.)
- Every probe is one ffmpeg run; success = exit 0 within its timeout; anything else (spawn error, timeout, non-zero) = failure. `kill_on_drop`. `[ts:T/hw-detect.ts:127]`
- `FLIKS_OPENCL_DEVICE` (`platform.device` selector) pins the NVENC/AMF OpenCL tone-map device, read from the environment as in the TS. `[ts:T/hw-device.ts:105-110]`

## 1. Wire mapping

Both are computed from one `Detected` state; `fixtures/hw/*.json` `expected` is what the TS ends in, serialised by the harness. `[new]` for the serialisation, the state is TS's.

## 2. Backend choice `[ts:T/hw-detect.ts:112-135]`

First one-frame encode that exits 0, 10 s each, argv `-hide_banner -loglevel error <device init> -f lavfi -i color=black:s=320x240:d=0.1 ... -c:v h264_<x> -frames:v 1 -f null -`:

| Platform | Order |
|---|---|
| darwin | videotoolbox |
| win32 | qsv (native `qsv=qs`, filter `format=nv12,hwupload,vpp_qsv=w=160:h=120:format=nv12`), amf, nvenc |
| other | qsv (`vaapi=va:<node>` + `qsv=qs@va`, filter `hwupload,format=qsv`), vaapi (`format=nv12,hwupload`), nvenc (`-hwaccel cuda`) |

None passes: `none`. The render node is `gpuRenderNode` when pinned, else `/dev/dri/renderD128` (even if absent). `[ts:T/hw-device.ts:16-26]`

## 3. Decoder probes (all descriptors, whatever the backend) `[ts:T/codec/decoder-probe.ts:33-100]`

1. One sample per source codec (h264 `libx264`, hevc `libx265`, av1 `libsvtav1`; `-y`, 320x180, 1 frame, yuv420p, 10 s) at `<tmp>/fliks-decoder-probe-<codec>-<pid>.<ext>`. Sample missing (encoder absent): that codec's decoders are disabled.
2. Per decoder, `supports()` false (qsv-vaapi: not win32; D3D11 kinds: win32; videotoolbox: darwin) = disabled without a run. Else its input args + `-i <sample> -frames:v 1 [-vf hwdownload,format=nv12 when frames stay on the GPU] -f null -`, 10 s. The software decoder (`cpu`) uses the h264 sample.
3. Samples are deleted afterwards. Decoder argv: `core/src/hw/decoders.rs` `[ts:T/codec/decoders/*.ts]`.

## 4. Encoder probes `[ts:T/codec/encoder-probe.ts:88-185,247-310]`

- Probed accels: the detected one, `none`, and vaapi when the detected one is qsv. Others are disabled without a run.
- `supports()` false (AMF off win32) = disabled without a run.
- One run per descriptor, 10 s: `<device chain> -frames:v 1 [-vf format=<nv12|p010le>,hwupload[,format=qsv]] <descriptor args> -f null -`. Input `nullsrc=size=320x180:rate=30,format=<yuv420p|yuv420p10le>`. The descriptor args are `buildArgs()` for a 320x180, 1 Mbps, gop 48 target with `veryfast`/`p4` presets, minus `-vf`: constants in `core/src/hw/encoders.rs`, not read from settings (so the QSV preset setting never reaches detection).
- `vaapiWritesHdrMetadata`: only when a VAAPI HDR10 descriptor is probeable; `-loglevel verbose` + VAAPI device init on a 64x64 nullsrc, true if the log has `VAAPI driver: Intel iHD` (case-insensitive, any whitespace). `[ts:T/codec/encoder-probe.ts:51-80]`

## 5. libfdk `[ts:T/audio-encoder-probe.ts:21-35]`

`ffmpeg -hide_banner -encoders` (10 s); `libfdk_aac` as a whole word (`\b`, `_` counts as a word char). The TS reads no other listing: `-decoders`, `-filters`, `-hwaccels` are not parsed (the test encodes are the truth).

## 6. GPUs `[ts:T/gpu-registry.ts:71-125]`

`/dev/dri` entries `^renderD\d+$`, sorted; vendor/device/boot_vga from `/sys/class/drm/<name>/device/` (trimmed; missing = empty). Vendor `0x8086` intel, `0x10de` nvidia, `0x1002` amd, else the raw id. Kind: nvidia, amd, intel+`boot_vga=1` iGPU, intel otherwise dGPU, else unknown. Label: `<Vendor> <model> · <kind> · <node>` for `0xa7a8` (Raptor Lake UHD Graphics) and `0x5693` (Arc A370M), else `<Vendor> <kind> · <node> (<vendorId>:<deviceId>)` with `?` for an empty id. No `/dev/dri` (Windows, macOS): empty.

## 7. Tone-map probes by backend `[ts:T/transcoding.service.ts:323-375]`

Run after decoders and encoders, serial; the HDR sample (`libx265`, 8 frames of 320x180 yuv420p10le BT.2020 PQ, 15 s, `<tmp>/fliks-<probe>-probe-<pid>.hevc`) is made per probe and deleted after; a failed sample fails the probe closed.

| Backend | Probes (probe names set on pass) |
|---|---|
| qsv | `vppQsv` (`vpp_qsv=tonemap=1`, 15 s); win32 also `qsvOpencl` then `qsvOpenclHdr10` (only if the first passed) |
| qsv or vaapi, not win32 | `tonemapOpencl` (20 s); only if it passed: `tonemapOpenclCrop`, `tonemapOpenclHdr10` |
| nvenc or amf | `opencl` then `openclHdr10` (only if the first passed), 20 s |
| vaapi on linux | `vulkan` (libplacebo, 20 s) |
| nvenc | `cuda` then `cudaHdr10` (only if the first passed), 15 s |
| amf | `amfOpencl`: the SDR tone-map run and the 10-bit scale run must both pass, 15 s |

Exact argv: `core/src/hw/probe.rs`; the fixtures pin every argv and timeout (as a set: the TS runs CPU probes in parallel, the port serially).

## 8. Pause capability `[ts:T/ffmpeg-pause.ts:44-117]`

`ffmpeg -hide_banner -loglevel error -nostats -re -f lavfi -i testsrc=size=320x240:rate=30 -t 600 -c:v rawvideo -progress pipe:2 -f null -`, stdin piped, last `frame=N` from stderr, killed at the end, 12 s overall. Timeline: 0.9 s write `p`; +1.5 s `settle`; +1.5 s `check`: `check > settle+3` = key ignored, stop; else write `u`; +1 s `after`: pause works iff `after > settle`. Works = `stdin`; else `none` on win32, `signal` elsewhere. Run once per process (it does not depend on the node). `pause_step()` in core decides, the fixtures store the three samples. The TS reads the first `frame=` of each stderr chunk; the port reads the latest line (same verdict, less lag).

## 9. Scheduling and settings

- Boot: detection starts at process start, in the background, with `auto`. `[ts:T/transcoding.service.ts:143-169]`
- `PUT /v1/config` changing `streaming.gpuRenderNode` (as `auto`/empty = none) runs the whole detection again on the new node, one run at a time, requests during a run coalesce into one follow-up on the latest node. `[ts:T/transcoding.service.ts:276-320]`
- Fixtures with a pinned node (`jellyfin-arc-pinned`) model "boot on auto, then re-pin"; their `expected.commands` are the commands since the re-pin plus the libfdk listing.

## 10. Where the port differs from the TS

- Each run recomputes every flag from scratch; the TS keeps flags of probes a re-pin did not re-run (a QSV to VAAPI re-pin keeps `vppQsv` true). `[ts:T/codec/vpp-qsv-probe.ts:15]`
- The TS applies the pinned node before the encoder/decoder probes but runs the backend choice on the default node at boot; the port uses the pin everywhere and re-runs when the first config pins one.
- `qsvPreset` is not read (section 4); `disabledEncoders` are probe results, not a setting.
- CPU probes run serially (the TS parallelises them); the result does not depend on it.
- The TS lists `vaapi` among `tonemapAlgos` for win32 QSV (no VAAPI there); kept, `[assumed]` harmless.
- Platform branches never run on a real host here: nvenc, amf/win32 and videotoolbox/darwin vectors are synthetic (scripted ffmpeg answers), see `docs/tests.md`.
