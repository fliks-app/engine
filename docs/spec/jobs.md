# Spec: background jobs (M5)

Work the host asks for outside playback: one generic job system (`engine::jobs`) with an extensible kind enum, a priority, cancellation, progress and a disk check, sharing one ffmpeg slot budget (`engine::slots`) with playback. Kinds: `Sprite` (the reference), `Scan`, `Fingerprint`, `SubtitleExtract`, `Cover`, `Merge`. Pure parts in `core::jobs`, IO in the engine. Tags are relative to `fliks/backend/src/` (`thumb` = `modules/streaming/thumbnail.service.ts`, `ext` = `modules/streaming/thumbnail-extractors/`, `slots` = `common/utils/ffmpeg-slots.ts`). Plan: sections 5, 14 (M5), M9.

## 1. Wire (`core::api::jobs`)

- `POST /v1/jobs` `JobRequest { kind, media: MediaRef, priority?, force? }` -> `{ jobId }`. `kind` is tagged by `type`: `{ type: "Sprite", info }`, `{ type: "Scan", info }`, `{ type: "Fingerprint", window: { type: "head" } | { type: "outro", durationSeconds }, maxLookupMinutes? }`, `{ type: "SubtitleExtract", info }`, `{ type: "Cover", info }` (`info` = `MediaInfo`), `{ type: "Merge", parts: [{ path, info }], output, tags? }` (section 10). An identical request (same `kind` and `media`, priority and `force` ignored) still queued or running answers its `jobId`: one run, one `BgJobDone`. 400 on a relative path or an unusable request (sprite without a positive `info.durationSeconds`, scan without a video stream, an outro fingerprint without a positive `durationSeconds`, subtitle extraction with no text track in `info.subtitles` or a stream index above 999, a cover without `info.cover`, a merge with no part, a non-audio part or an `output` that is not an absolute `.m4b`, a kind that does not apply to the family of `info`, section 9). [new]
- `GET /v1/jobs` -> `[JobSnapshot]` (oldest first), `GET /v1/jobs/{id}` -> `JobSnapshot` or 404. `JobSnapshot { jobId, kind, mediaFileId, priority, state, pct, createdMs, startedMs?, endedMs?, result?, error? }`; `state`: `queued`, `running`, `paused` (every run it holds is preempted), `done`, `failed`, `cancelled`. Ended jobs stay listed: the last 200. [new]
- `DELETE /v1/jobs/{id}`: 204 (a queued job leaves the queue, a running one is stopped through `proc` section 1's stop, an ended one is untouched), 404 when unknown. [new]
- Events: `BgJobProgress { jobId, pct }` at most once per second per job while it runs (`pct` 0 to 100, f64); `BgJobDone { jobId, state, result?, error? }` once per job (`state` done/failed/cancelled; `result` on done, `error` otherwise). Results are data (`JobResult`, tagged by `type`: `Sprite { sprite }`, `Scan { scan }`, `Fingerprint { fingerprint }`, `SubtitleExtract { streams }`, `Cover { cover }`, `Merge { merge }`): files a job writes stay in the engine's cache and are served by the data plane, never handed to the host as a path (M9: no shared filesystem). [new]
- `hello.features` gains `jobs`, `scan`, `fingerprint`, `subtitle-extract` (later `cover`, `merge`).

## 2. Queue and lifecycle

- At most 2 jobs run at once (`SPRITE_CONCURRENCY` [ts:thumb:56]); the others wait in a queue ordered by `priority` (`high`, `normal` default, `low`), then arrival. [ts:thumb:245-270] (FIFO only there)
- Urgent (engine-internal, a session open waiting on the job: `docs/spec/runtime.md` section 9): the job starts at once past that limit, its runs take a playback slot (section 3) without the background `ionice`/`nice`, and are never preempted. An identical queued job is promoted and started; a running one is promoted: a preempted run resumes and the run in flight leaves the idle class in place (`setpriority` and `ioprio_set` on its process group) when the OS allows it (CAP_SYS_NICE or RLIMIT_NICE). Otherwise the run is stopped, its background slot released, and the job starts over from its first step on playback slots, still the same job: one `jobId`, one `BgJobDone`, the waiters unchanged. [new]
- A job that writes files first checks the free space of the cache root's filesystem: below `streaming.jobMinFreeBytes` (default 1 GiB, 0 disables) it ends `failed` with `not enough disk space: <free> bytes free under <dir>, jobMinFreeBytes is <min>`. Checked once the job runs, before it writes (an existing sprite, or subtitle tracks all cached, answered without a write skip it). [new]
- Cancellation (DELETE, `POST /v1/invalidate` of its file, engine shutdown) stops the job's ffmpeg runs (SIGTERM, SIGKILL after 2 s), removes its temporary files and ends it `cancelled`. Shutdown awaits every job. [new]
- Invalidate also deletes the file's engine sprite (`sprites/v1/<file>`). [new]

## 3. ffmpeg slot budget (`engine::slots`)

One budget for every ffmpeg the engine runs: playback (session runs, I-frame and subtitle extracts), background job runs and probe crop samples. [ts:slots]

- Size: `streaming.ffmpegSlots` when set and > 0, else `max(1, cores - 1)`, `cores` = `available_parallelism` (CPU affinity and cgroup v1/v2 quota already applied). Read at every `PUT /v1/config`. [ts:slots:47-54,79-85]
- Playback never waits: it takes a slot at once, even past the size. A hardware encode (VAAPI, NVENC, QSV, AMF, VideoToolbox) does not consume that budget, so on 2 cores two of them leave the one background slot running; a software transcode, a remux and a short extract still take one. `playback_in_use` counts both, so a sprite still leaves the GPU to playback. A throttled (paused) session run gives its slot back while paused. [new] (the TS pool held background work only)
- Background: `allowed = size - playback in use` (floor 0). Holders are granted FIFO within a priority, newest last; the first `allowed` holders run, the ones past it are preempted: paused through the host's pause capability (`signal`: SIGSTOP the group, `stdin`: `p`) and resumed (`u`, SIGCONT) when playback releases its slots, oldest first. Without a pause capability a preempted run keeps going (it runs under `ionice -c3 nice -n19` on Linux), and no new background run starts until `allowed` grows. [ts:slots:93-122] (FIFO, no preemption)
- A shrunk size preempts the same way (the TS lets running work drain). A queued waiter that gave up (cancelled) is skipped.
- Weights: `background(priority, weight)`; every holder counts `min(weight, size)` against `size - playback` (recomputed in each `rebalance`, so a smaller `set_size` never blocks a heavy run forever). Whom to pause is decided by (priority, age) over the summed weights: the lowest priority and the newest yield first. A waiter of another kind takes the room of a running optimization (rank below `low`) without waiting; it never displaces other background work. A software optimization weighs `cpuWeight` (default 2), a GPU one 0. [new]
- Optimization lanes: `Slots::optimize(Lane { device, gpu })` is outside `MAX_RUNNING` (leased jobs start at once, `jobs::submit_leased`) and has its own per-device limit (`set_device_limit`, default 1, the `maxJobs` of `hello`). Threads follow the weight: `-threads`, x265 `pools` and SVT-AV1 `lp` = `weight x quota / size` (`ArchiveRate.capPools`). [new]
- GPU reserve: a GPU lane is preempted as soon as the hardware playback reads of its device reach `gpuPlaybackBeforePause` (default 1, 0 never), and does not start meanwhile; the CPU lane is unaffected. [new]
- A preempted optimization where ffmpeg cannot be suspended (no pause capability, or `FLIKS_OPTIMIZE_PAUSE=restart`) is killed instead and ends `busy: ...`: the worker loop reports it as class `busy`, which the host requeues without a failure. The heartbeat carries `paused: true` while every run of the job is held. [new]
- Probe crop samples take background slots (they used their own `cores - 1` semaphore). [ts:modules/media-probe/ffprobe.service.ts]

## 4. Background runs

- Spawned through `proc::Ffmpeg` (own process group, kill-on-drop, `PR_SET_PDEATHSIG`) behind `ionice -c3 nice -n19` when both are on PATH (Linux). [ts:common/utils/spawn-priority.ts] Every tool of a job goes through `Ctx::pipeline`: one slot for one process or for a pipeline of several (ffmpeg + fpcalc of a window), paused and stopped together. Binaries: `ffmpeg` (`FFMPEG_PATH`), `ffprobe` (`FFPROBE_PATH`), `fpcalc` (`FPCALC_PATH`, default `fpcalc`).
- Every 200 ms: the slot's pause verdict is applied; `core::session::job_watch` (stderr lines and CPU time are progress, paused time exempt, `jobStallTimeoutMs`) kills a hung run, and a run past its timeout of unpaused wall time (30 s for a sprite frame or tile, the kind's own below) is killed. Either is a run failure (`<tool> stalled` / `<tool> timed out`). Bytes of the source read and lines parsed count as progress for the watchdog (`Ctx::pulse`), as stderr lines and CPU time do. [ts:thumb:672-690,735-745]

## 5. Sprite (`core::jobs::sprite`, `engine::jobs::sprite`)

Input: `media.path`, `info`. Output: `<cacheRoot>/sprites/v1/<mediaFileId>/sprite.jpg` and `sprite.json`; result `{ type: "Sprite", sprite: SpriteMeta }`, `SpriteMeta { interval, columns, thumbWidth, thumbHeight, count }` = the `sprite.json` text. [ts:thumb:35-41]

- Existing: without `force`, a readable `sprite.json` ends the job `done` at once with its contents. [ts:thumb:163-174]
- Duration `d` = `info.durationSeconds`. Interval: `d < 300` -> 2, `d <= 3600` -> 5, `d <= 7200` -> 15, else 30. `count = ceil(d / interval)`, `columns = 10`, `rows = ceil(count / 10)`, `thumbWidth = 240`. [ts:thumb:285-287,780-785]
- Seek offset = `input_seek_seconds(0, source_timeline(info))` (tile times count from the first frame); HDR = `video[0].colorTransfer` is `smpte2084` or `arib-std-b67`; crop = `video[0].crop`. [ts:thumb:139-150,43-47]
- Frame `i` (0-based) at `i * interval + offset`, written to `frames/frame-<i+1, 4 digits>.jpg`, one ffmpeg each, `min(slots size, count)` workers. A failed frame is logged and extraction goes on; missing frames are then filled from the nearest present one (lower first at equal distance) so the tiler's sequence has no gap. The job fails only when no frame at all was extracted (`Sprite failed: no frame could be extracted (<n> attempts)`). [ts:thumb:495-660] (the TS stops at 5 failures and fails above `count * 0.1`)
- Extractor (`pick_extractor`): darwin: VideoToolbox; linux: VAAPI on the detected render node when the host runs `vaapi` or `qsv` and there is no crop, QSV for a crop on a `qsv` host, CUDA on an `nvenc` host, else software; software whenever a playback run holds a slot (the GPU belongs to the transcode). [ts:ext/index.ts:20-75] [ts:thumb:103-113]
- Argv per extractor: [ts:ext/sw.extractor.ts] [ts:ext/vaapi.extractor.ts] [ts:ext/qsv.extractor.ts] [ts:ext/cuda.extractor.ts] [ts:ext/videotoolbox.extractor.ts] [ts:ext/tonemap.ts]; seek printed as JS `String(x)`.
- Tile: `-nostdin -hide_banner -loglevel error -start_number 1 -i <frames>/frame-%04d.jpg -vf tile=10x<rows> -q:v 5 -y <out>`. [ts:thumb:710-735]
- `thumbHeight = round(jpegHeight / rows)` from the tiled JPEG's frame header, 90 when unreadable. Written as `sprite-tmp.jpg` then renamed, `sprite.json` last; frames removed. [ts:thumb:404-420]
- Progress: `pct = 100 * frames done or failed / count`, capped at 99 until the tile lands.
- Serving: `/api/stream/:id/thumbnails/sprite.{json,jpg}` still asks the resolver (`purpose: sprite`, a grant without `path` is accepted for this purpose only), then serves the engine's file when present, else the resolver's `path` (sprites the host generated before M5), else 404.

Golden vectors: `fixtures/jobs/sprite/*.json` (layout, frame argv, tile argv, seek offset, backfill), recorded once from the TS, Rust-owned since (`BLESS=1`).

## 6. Scan (`core::jobs::scan`, `engine::jobs::scan`)

Input: `media.path`, `info` (a video stream). Output: result `{ type: "Scan", scan: SourceScan }` (`schemaVersion` stamped), the decide input's `scan`; no file. Argv, reader rules and timeouts are `docs/spec/jobs-pure.md` section 1. [ts:modules/streaming/services/source-scan.ts, video-packets.ts]

- Reorder lead: known from `info` when it has `reorderFrames` and `avgFrameRate`, else one `ffprobe` read of the stream (30 s), first line.
- Packets: `ffprobe` on the file (stdout read line by line, `PacketReader::feed_line` until the clock breaks: ffprobe is then stopped), timeout `scan_timeout_ms(size)`. Progress: `pct` = source time read / `info.durationSeconds`, capped at 99.
- MPEG-TS with AAC tracks (every OS): a first short `ffprobe` (`stream=index,id`, 30 s) gives each AAC track's PID. Then the engine reads the file once, in 1 MiB chunks, and feeds the same bytes to ffprobe (`pipe:0`) and to a `core::mpegts::Demuxer`, which walks the ADTS headers of those PIDs with one `AdtsConfigWalker` each (no extra process). ffprobe stopping (clock break) stops the read. `audioConfigChanges` is `true` for a track with no PID in the ffprobe answer, whose PES cannot be parsed or whose PID the PMT says is not ADTS; the other tracks keep their own verdict. The packet pipeline = one slot.
- Failure: a non-zero ffprobe exit not asked for is `ffprobe exited N: <stderr>`; no packet with a time is `no video packet with a time`.

## 7. Fingerprint (`core::jobs::fingerprint`, `engine::jobs::fingerprint`)

Input: `media.path`, `window`, `maxLookupMinutes` (absent or 0: 10). Output: result `{ type: "Fingerprint", fingerprint: Fingerprint }`; no file. [ts:modules/markers/intro-detection.service.ts:815-940]

- `head`: `fpcalc -raw -length <lookup> <path>` (the file's first `lookup` seconds, `baseOffsetSec` 0), 180 s.
- `outro { durationSeconds }`: the window `[max(0, d - lookup), lookup]`, ffmpeg's WAV on stdout piped into `fpcalc -raw -length <lookup> -` (one slot for the pair, 180 s), `baseOffsetSec` = the unfloored start. Progress: WAV bytes piped / the expected size, capped at 99.
- Failure: fpcalc exiting non-zero is `fpcalc exited N: <fpcalc stderr, else ffmpeg's>`; no `FINGERPRINT=` line is `fpcalc returned no FINGERPRINT line`.
- Matching, clustering and markers stay on the host.

## 8. SubtitleExtract (`core::jobs::subtitles`, `engine::jobs::subtitles`)

Input: `media.path`, `info` (its non-image `subtitles` are the tracks). Output: `<cacheRoot>/subtitles/v2/<mediaFileId>/<stream>.vtt` per track; result `{ type: "SubtitleExtract", streams }` = every text track's stream index, served by the subtitle routes (`embedded/{idx}`). [ts:modules/streaming/subtitle-stream.service.ts]

- Tracks whose codec ffmpeg converts to ASS only: bitmaps, `dvb_teletext`, `ttml`, `hdmv_text_subtitle` and an unknown codec are left out (`converts_to_ass`). Tracks already cached are skipped unless `force`; none left to extract: `done` at once. Otherwise the disk check, then one ffmpeg run for every missing track (`extract_args`, raw ASS next to the targets, 15 min), `check_extracted`, `ass_to_vtt`, written atomically (`<idx>.vtt.<rand>` then rename), raw files removed. One bad track (empty file, write error) does not hold back the others: the job then fails with `stream <n>: <error>` for each. Progress: tracks converted / tracks, capped at 99.
- Unified path: `GET .../subtitles/embedded/{idx}` on a cache miss runs the job's extraction (disk check, one `extract_args` run for every uncached convertible track, `convert_raw`) and, when that run leaves the requested track uncached, retries it alone, so the served text equals the job's output byte for byte (`runtime_jobs`, `runtime_e2e` compare them). `X-TIMESTAMP-MAP` is added at serve time only. External subtitles still go through `ffmpeg -f webvtt`.
- The cache is `subtitles/v2`: the `-f webvtt` extracts of `subtitles/v1` are purged at start.

## 9. Cover and job families (`core::jobs::cover`, `engine::jobs::cover`)

Input: `media.path`, `info` with a `cover` (`probe.md` rule 12). Output: `<cacheRoot>/covers/v1/<mediaFileId>/cover.jpg` or `cover.png`; result `{ type: "Cover", cover: { mime, bytes } }`. [new]

- One ffmpeg run, `-map 0:<cover.streamIndex> -an -sn -dn -frames:v 1 -fs 16777217 -f image2 -update 1`: `-c:v copy` for an `mjpeg` or `png` stream (stored as `.png` for PNG, `.jpg` otherwise), else `-c:v mjpeg -q:v 2`. Written as `cover-tmp-<rand>.<ext>` (one per run) then renamed over the stored file, the other format's file removed after; an empty output fails the job (`ffmpeg wrote no picture`), so does one over 16 MiB (`cover too large`, `-fs` stops ffmpeg one byte past it).
- Existing: without `force`, a stored cover ends the job `done` at once. The disk check runs before a write. `POST /v1/invalidate` deletes it.
- Reading: `GET /v1/covers/{mediaFileId}` on the control plane (bearer): the stored picture with its `Content-Type`, streamed from disk, 404 when none. A control route, not a data-plane one: the host stores covers at ingest, no end user credential is involved.
- Families: a file is `video` when `info.video` is not empty, else `audio` when `info.audio` is not empty (`MediaInfo::family`). `hello.jobFamilies` lists each kind and the families it applies to: `Sprite`, `Scan`, `Fingerprint`, `SubtitleExtract`, `SubtitleOcr`, `SubtitleToSrt` apply to `video`, `SubtitleSync` to both (it aligns on the audio), `Cover` to `audio`. A host queues only matching work (it derives the family from the probe). `POST /v1/jobs` enforces it where the request carries `info`: 400 `<kind> does not apply to <family> files`. `Fingerprint` carries no `info`: the host filters it. A reader treats a family it does not know as `unknown` (`MediaFamily`, additive). `hello.features` lists `cover`.

## 10. Merge (`core::jobs::merge`, `engine::jobs::merge`)

Input: `{ type: "Merge", parts: [{ path, info }], output, tags? }`; `media` names the first part (cancel, invalidate and the dedupe key use it). Output: the `.m4b` at `output`; result `{ type: "Merge", merge: { path, bytes, durationSeconds, chapters, reencoded } }` (`bytes` is f64). The one kind that writes where the host says instead of the engine cache; it applies to the `audio` family and `hello.features` lists `merge`. [new]

- Validation (400): 1 to 500 parts; every part an absolute path, an audio file (`info.family()`) with a positive `durationSeconds`; `output` an absolute `.m4b` path. A path with a control character (a newline would start a directive of the concat list, which is read with `-safe 0`) is refused for the parts and the output.
- Encoding (`core::jobs::merge::encoding`): the packets are copied (`-c:a copy` through the concat demuxer) when every part has the same container (`info.formatName`: no ADTS `.aac` next to `.m4a`) and the same first audio stream: AAC, same sample rate, channel count, profile and stream index. Anything else is encoded to AAC: the parts' first audio streams go through the `concat` filter (which converts rates and layouts) and one `aformat` to the first part's sample rate (at most 96 kHz) and mono or stereo (at most 2 channels). Bit rate = the highest of the parts' rates, between 32 kb/s and 128 kb/s per channel; a lossless part counts as 64 kb/s per channel (speech), and so does a part whose rate is unknown. `reencoded` says which.
- Command line: the filter graph is a file (`-filter_complex_script`), so only the `-i <part>` pairs grow with the part count. On Windows the engine refuses, before the run, a command line over 30000 characters (the limit is 32767): about 500 parts with paths of 55 characters, or 240 with paths of 120; the copy path has a fixed-size command line whatever the count. Elsewhere only the 500 parts apply.
- Chapters: a part with `info.chapters` contributes them, moved to the part's place (the sum of the durations of the parts before it) and clamped to its duration, an untitled one named `Chapter N`; a part without any is one chapter titled from its `tags.title`, else `Part N`. They are also returned in the result.
- Cover: the first part with `info.cover`, copied when `mjpeg` or `png`, else encoded to JPEG, as the attached picture.
- Tags: the request's `tags` win (values go into the ffmetadata file with `=`, `;`, `#`, `\`, newline and carriage return escaped, NUL dropped and trailing backslashes stripped), then the first part that has the field. The title is the request's, else the parts' album, else the first part's title (a part's own title names its chapter); the album is the request's `album`, else its `title`, else the first part's album, else the title. Track and disc numbers are dropped. The MP4 muxer writes the title, album, artist, album artist, composer, genre, description and year as iTunes atoms; the narrator, publisher, language, series, series part, ASIN and ISBN have none and are added afterwards as free-form atoms (`----`, mean `com.apple.iTunes`, the probe's tag names) to the `ilst` of the `moov`, in place. That needs the `moov` last in the file, so the output is not `faststart`.
- Run: `-progress pipe:1` lines on stdout are the progress (`out_time_us` over the summed durations, capped at 99); stderr and the lines feed the stall watchdog; the run's ceiling is one hour plus the summed durations of unpaused time. Background slot, pause on playback and cancel as any run (`Ctx::pipeline`).
- Files: the concat list and the ffmetadata file live in `<cacheRoot>/merge/v1/<jobId>` and are removed when the job ends. The mux goes to `<dir>/.<name>.merge-<rand>.tmp` beside `output` (its directory is created), is flushed (`fsync`) and published with a hard link, which fails when `output` exists, else (no links on that filesystem) `renameat2(RENAME_NOREPLACE)` on Linux, or a check and a rename where the kernel or filesystem lacks it and on other platforms; the temporary file is removed on failure, cancel and success. An existing `output` fails the job (`output exists: <path>`) before any work, `force` does not change that. The free-space check (`jobMinFreeBytes`) is made on the directory of `output`. The job creates the temporary file itself, exclusively (`create_new`; ffmpeg then overwrites it, `-y`), and writes `<cacheRoot>/merge/v1/<jobId>/tmp-path`: the output path, the temporary path and its `dev:inode`, one per line. The temporary file is removed only while the path still holds that inode, and the scratch directory goes after it. A crash can leave a `.tmp` file: at start, before any job, the engine deletes the file each leftover `tmp-path` names, only when it is `.<output name>.merge-<8 hex>.tmp` in the directory of the journaled output and still has the journaled inode, then the scratch. No other file is touched. This assumes one engine per cache root: the engine takes an exclusive `flock` on `<cacheRoot>/.lock` at start (Unix) and exits with an error when another holds it.
- Paths go through `pathMappings` like `media.path`, `output` included.

## 11. Optimize and Verify (`core::jobs::optimize`, `engine::jobs::{optimize,verify}`) `[new]`

The library optimizer's executors (plan: batches E3/E4). They run as ordinary jobs on a background slot (`POST /v1/jobs`, or the worker loop from a lease); the lease's `stagedPath` goes into `OptimizePayload.stagedPath`. A failure is `<class>: <message>` (`JobErrorClass::message`/`from_message`; classes in `PROTOCOL.md`), the worker loop turns it into `JobResultRequest.error`.

**Optimize.** `media.path` is the source (through `pathMappings`), `stagedPath` the output (absent: `.fliks-opt-<jobId>-1.tmp` beside the source). The plan is executed as written; the three levels:

- `metadata` (MKV only, no track removed, converted or added): the source is copied into `staged` (`FICLONE` reflink on Linux when the filesystem has it, a full copy otherwise), then `mkvpropedit` (`MKVPROPEDIT_PATH`) edits the copy: `language`, `name` (`""` deletes), `flag-default` per `streams[]`, `--delete title` on the info element (`clearTitle`), and always `--add-track-statistics-tags` (`stripStatisticsTags` is ignored). The free space is checked only when the reflink fails and a full copy is needed (`nospace` before it starts). Tracks are addressed by type and rank (`track:a2`), never by number. No ffmpeg, so no decode check.
- `remux`: `args::file` with `copyVideo` and the `ArchiveFile` built by `optimize::archive_file`: kept streams by index, `encode` (E-AC-3 or AAC, `args.md` section 14) replaces the track or, with `keepOriginal`, follows it (the original keeps its own tags, `title`/`default` go to the new track), `extraSubtitles` (the OCR'd SRT of an image track) are extra inputs mapped after the kept subtitles. Image subtitles cannot go to MP4 (refused). The output container is `plan.container`, else the source's (MP4/MOV stay MP4). `default` is written as `+default`/`-default`, so `forced`, `comment`, `hearing_impaired`... survive; `clearTitle` writes `-metadata title=` (`-map_metadata 0` would carry it). Every Matroska output (remux or re-encode) then goes through `mkvpropedit --add-track-statistics-tags`, before the checks.
- `reencode`: the video is copied (`copyReason: unsupported_source`) when the source is interlaced (`fieldOrder`), 4:2:2/4:4:4 on a hardware encoder, Dolby Vision profile 5, DV 7/8 or HDR10+ while `skipHdr10plusDv` (default true), (10-bit SDR is encoded: HEVC keeps the source's depth, AV1 is always 10-bit). Otherwise up to three 20 s windows (evenly spread; one under 2 min, none under 20 s) are encoded and the same windows copied, video only, into `<cache>/optimize/.fliks-opt-<jobId>.sample<k>{s,e}.mp4` (never beside the source; the engine removes leftovers at startup): a saving below `minSavingsPct` copies the video (`low_savings`). A software encode (`software`, or no accelerator) estimated above `maxSoftwareHours` (default 12) switches to the hardware encoder (`tooSlow: hardware`, default), or copies the video (`too_slow`) with `tooSlow: skip`, without an encoder, or on the `cpu` lane (which never takes the GPU). A video file's cover (`info.cover`, an `attached_pic` stream) is mapped and copied. After the encode the saving of the produced video track (ffprobe packet sizes) is checked again: below the threshold the output is redone as a remux (`low_savings`). Hardware is the default; quality is `plan.quality` (default balanced).
- `OptimizeMeta.level` is what was done (a re-encode that copied the video is `remux`); `copyReason` says why.

**Safe writing.** `safe_write::create_staged`: `create_new` (never `create_dir_all`, a taken name fails the job and is never removed), the directory's `st_dev` must equal the source's, mode and owner are the source's (`fchmod`/`fchown`, best effort). ffmpeg runs `-y` over that empty file. `safe_write::publish`/`rename_new` (extracted from Merge) publish without replacing; the server's commit step owns the swap, the engine only leaves `staged`. The staged file (and samples) are deleted when the job ends other than by `done`; a source whose size or mtime moved during the job fails `stale`. The staged directory is never created and the disk check does not create it either (a missing folder is `access`). Space: `jobMinFreeBytes` plus at least the source's size free beside `staged` (`nospace`), at every level but a reflinked metadata copy.

**Checks** (`optimize::verify_output` plus the engine's measurements; any failure is class `verify`):
1. video packet count equal to the source (`ffprobe packet=size`, both files);
2. the end of the video, of every audio and of every subtitle track within 1 s of its source track (a source whose `hasStatisticsTags` is `false` has no trusted `DURATION`: its audio and subtitle ends are skipped); the container duration only when the video has no end; video (and copied audio) start within one frame;
3. audio and subtitle tracks as the plan says (count, language, title, forced/SDH), chapter count;
4. re-encode: HDR10/HLG colour tags and mastering metadata equal; copy: `dvProfile`, `dvBlSignalCompatId`, `dvRpuPresent` equal;
5. `hvc1` in MP4 when planned; no `unknown` audio layout;
6. re-encode: `Scan` on the output, no gap between keyframes above 6 s (a copied video keeps the source's GOP, so it is not checked);
7. full software decode `-xerror` of the output (video 0 and every audio);
8. mean SSIM >= 0.9 on three 5 s windows (ffmpeg's built-in `ssim`, not VMAF), for hardware outputs and `faithful`, when there is no crop.
A hardware encode whose run fails, shows decoding errors or fails any check is redone on the CPU (`cpuFallback`); a second failure is final. Fallback does not wait for "the first second": any failed hardware run, sample encodes included, falls back, when its class is `engine` or `verify` (not `network`, `nospace`, `access`, `damaged`, `busy`, a cancel). A software encode of a job leased on `gpu0` re-enters the slots on the `cpu` lane with the CPU weight.

**Corrupt source.** The source is opened and stat'ed first (`ENOENT`/`EACCES`/`EROFS` -> `access`, `EIO` -> `io`). ffmpeg's stderr is read for failures (`classify_stderr`: `nospace`, `io`, `access`, `corrupt` for `moov atom not found`/`EBML header parsing failed`/`Invalid data found when processing input`, else `engine`) and its decode-error lines counted (`is_decode_error`, `non monotonically increasing dts` ignored). Any error on the final CPU run discards the output: `damaged` up to 10 errors per hour of film, `corrupt` beyond.

**Verify.** The file is read whole in Rust (`access`/`io`), then decoded in software with `-v error -f null`, errors counted without `-xerror`; none -> `VerifyMeta`, else `damaged`/`corrupt` as above, with up to three error lines.

**Time.** `Optimize` and `Verify` runs have no `RUN_TIMEOUT_MS` (`Ctx::run_timeout_ms`); the stall watchdog applies (stderr lines, `-progress` lines, CPU time, `pulse()`), and paused time never counts. Progress: 0-5 samples, 5-85 encode, 85-95 checks (decode, SSIM), then hash.

**Not done / open**: `stale` is detected only by size and mtime; `OptimizeMeta` has no decode-error count (an error fails the job); the cover art of a video file is not mapped (the probe only reports it for audio files); position of a decode error in the film is not reported; VMAF is replaced by SSIM; no `staged` age sweep (server side).

**Worker loop** (`engine::worker`, `PROTOCOL.md`): `jobs::submit_leased` runs a lease as an ordinary job on its device's lane (`cpu`, `gpu0`..`gpuN`, each GPU on its own render node); a job leased on `cpu` never takes the GPU whatever `plan.software` says. The lease's `inputPath`/`stagedPath` go in `media.path`/`OptimizePayload.stagedPath`. With `inputUrl` the source is read over HTTP (`opt::http_input`: bearer header, `-reconnect 1 -reconnect_on_network_error 1`) and a failed read is class `network`; the metadata level needs a local file. The worker leases for a device only while it has room (a free place, no GPU reserve reached, CPU budget left) and a job waiting for a slot reports `paused`. A 409 or `cancel: true` cancels the job (the executor deletes its files; the worker removes the staged output of a job already done); a result answered `404 unknown worker` is retried after a new hello, a network error or 5xx kills nothing until the lease has been unanswered for `leaseS`.

## 12. Adding a kind

A variant of `core::api::JobKind` (and `JobResult` when it returns data), its validation in `engine::jobs::submit`, its pure part in `core::jobs`, a branch in `engine::jobs::run` calling its module. That module gets a `Ctx`: `ffmpeg(argv)` for one ffmpeg run and `pipeline(timeout, cmds, work)` for any tools (one background slot, pause, watchdog, stop on cancel; `Cmd` names the binary and whether its stdout is exposed; `work` drives them), `pulse()`, `progress(pct)`, `cancelled()`, `check_disk(dir)` before writing under the engine cache, `media_path()`.

## 13. Deviations

- Playback counts against the budget and preempts background runs; the TS pool held background work only, FIFO, with no pause. A shrunk budget pauses (TS: drains).
- The sprite extractor follows the detected backend and render node (TS: `/dev/dri/renderD129`/`128` and `/dev/nvidiactl` existence, `THUMB_HWACCEL_DEVICE`); QSV crop only on a `qsv` host, nothing but software on Windows (as the TS).
- Sprite failed frames: as the TS backfills, but extraction never stops at 5 failures and there is no `count * 0.1` threshold; only a job with no frame at all fails.
- `thumbHeight` comes from the JPEG header, not `ffprobe`; per-run timeouts count unpaused time only; no global 10-minute sprite timeout (the watchdog covers hung runs).
- Sprites live in the engine cache (`sprites/v1`), not `<cacheDir>/thumbnails`; the host's activity/command rows and `task.progress` become `BgJobProgress`/`BgJobDone`.
- Scan: the engine reads the file itself (tokio) for the piped MPEG-TS case, not `cat` under `ionice`, and a native demuxer reads the ADTS headers in that one pass on every OS (the host runs a second ffmpeg). Progress and the slot, pause and watchdog framework are new.
- Fingerprint: the head read and the window pipeline run under a background slot (the TS: `withFfmpegSlot` too), ffmpeg of a window is stopped once fpcalc has its `-length`.
- SubtitleExtract: a job form of the host's warmup (no Command rows, `subtitlePrewarm` stays the host's call); a track missing from `info` is not extracted.
- Merge: the output is written where the host says, not into the engine cache; it fails on an existing file instead of replacing it, and is not `faststart` (free-form tags are added to the `moov` in place).
