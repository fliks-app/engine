# Tests

- `crates/core/src/api.rs` (unit): MediaInfo/DeviceProfile/SourceScan round-trip equal to the host JSON, unknown fields ignored.
- `crates/core/tests/decide_fixtures.rs`: every `fixtures/decide/*.json` input (`info`, `device`, `scan`) round-trips the wire types, and `decide(input, hostCaps, config)` equals `expected` (numbers compared as f64; mismatches print the fixture name and the differing JSON paths; explicit `SKIPPED` allowlist, empty). Vectors come from the host harness `backend/test/engine-vectors` (`FLIKS_ENGINE_REPO=<this repo> npx jest test/engine-vectors`), see `docs/spec/decide.md`.
- `crates/core/tests/estimate_fixtures.rs`: every `fixtures/estimate-sizes/*.json` (`input` = `{info, fileSize}`, `expected` = the host controller's `downloadQualities` result) through `estimate_sizes()`. Generated by the same harness run as the decide vectors (`FLIKS_ENGINE_REPO=<this repo>`), see `docs/spec/estimate-sizes.md`.
- `crates/core/tests/decide_fuzz.rs`: differential fuzz, no-op unless `DECIDE_FUZZ_DIR` is set. Replays every `*.ndjson` there (`{seed, i, input, hostCaps, config, expected}`, `expected` = the TS `evaluate()`) through `decide()` with the shared comparison in `tests/common`, and prints mismatches grouped by first differing path (`DECIDE_FUZZ_EXAMPLES=<n>` examples per group, default 2). Named predicates in `EXCLUDED` skip classes recorded under Deviations (none). Last run: seeds 1-5 and holdout 6-7, 5 000 inputs each, 0 mismatches; promoted classes are `fixtures/decide/fuzz-*.json`.
  - Generate (host repo, seeded mulberry32): `cd backend && for s in 1 2 3 4 5; do FUZZ_OUT=/tmp/fuzz FUZZ_SEED=$s FUZZ_COUNT=5000 npx jest test/engine-vectors; done` (inputs the TS rejects are skipped and counted by message in `fuzz-<seed>.throws.json`).
  - Replay: `DECIDE_FUZZ_DIR=/tmp/fuzz cargo test -p fliks-engine-core --test decide_fuzz 2>&1 | tail -30`.
  - Promote a minimal mismatch as `fixtures/decide/fuzz-<slug>.json` (`name`, `source: "fuzz"`, `input`, `hostCaps`, `config`), then fill `expected` from the TS: `cd backend && FUZZ_EXPECT=<dir with the file> npx jest test/engine-vectors`.
- `crates/engine/tests/control_plane.rs`: bearer auth, hello, config revision rule, `POST /v1/decide` (400 before the first config, then the golden `android-tv-h264-sdr-mkv-cpu-720p` decision with a detected CPU-only host).
- `crates/engine/tests/control_plane.rs` also covers `POST /v1/estimate-sizes` (bearer, 1080p entry).
- `crates/core/tests/hw_fixtures.rs`: every `fixtures/hw/*.json` (`env` = `/dev/dri` + sysfs, `calls` = what each ffmpeg argv answered with exit code, stderr and the `-encoders` listing, `pause.samples`) through `core::hw::detect()` with a replay runner; `HostCaps`, `Capabilities` and the set of (argv, timeout) pairs run must equal the TS's `expected`; an argv with no recorded answer fails the test. Scenarios: `host-ffmpeg-no-driver`, `jellyfin-raptor-lake`, `jellyfin-arc-pinned` (recorded on this machine: Raptor Lake iGPU + Arc A370M, host ffmpeg 8.0.1 and the engine image's jellyfin-ffmpeg 8.1.2 with `--device /dev/dri`), and synthetic ones scripted by the harness: `linux-cpu-only`, `linux-vaapi-amd`, `linux-qsv-intel-ihd`, `linux-qsv-partial` (blacklisted ids), `linux-qsv-broken-vaapi-fallback`, `linux-gpu-broken-cpu-fallback`, `linux-nvenc`, `win32-amf`, `win32-qsv`, `darwin-videotoolbox`. nvenc, amf/win32 and videotoolbox/darwin are not real hosts: the argv come from the TS, the answers are scripted. Generated by `cd backend && FLIKS_ENGINE_REPO=<this repo> npx jest test/engine-vectors/hw-vectors` (re-record one real scenario with `FLIKS_HW_RECORD=<name>` on a machine that has it; `expected` is always recomputed by the TS from the stored answers), verified with `FLIKS_ENGINE_REPO_CHECK=<this repo>`; see `docs/spec/hw.md`.
- `crates/core/src/hw` (unit): `libfdk_aac` word boundary, iHD log match, pause verdict steps, the probe encoder table lists the same ids as the decision's registry.
- Live parity (manual): `FLIKS_HW_LIVE=<out.json> [FLIKS_HW_NODE=/dev/dri/renderD129] npx jest test/engine-vectors/hw-vectors` runs the TS detection for real; `target/debug/hw-detect [node]` prints the Rust one; compare the JSON (`capabilities`, `hostCaps`). In the image: mount the worktree and `node_modules` read-only at the same paths, `--device /dev/dri --group-add <render gid> --user 1000:1000`, run `node node_modules/jest/bin/jest.js`; mount the `hw-detect` binary and run it.
- `crates/engine/tests/hw.rs`: 503 + `Retry-After` on `/v1/capabilities` and `/v1/decide` until detection ends, then the detected caps; a `gpuRenderNode` change re-detects on the new node and coalesces pins made during a run. `crates/engine/src/hw/io.rs` (unit): render-node enumeration over a fake sysfs, a missing ffmpeg fails closed.
- `crates/engine/tests/supervise.rs` (unix): failing host is restarted with the injected env.
- CI drift: `openapi.json` matches the types; `oasdiff breaking` against main.
- `crates/core/tests/probe_fixtures.rs`: every `fixtures/probe/*.json` (not `_*`) replays the recorded output of ffprobe, mkvmerge and ffmpeg through `probe()` with a `Tools` stand-in; the result must equal the host's `{ ok, info }` (comparison in `tests/common`; `expected.nulls` are paths the host writes as `null`, absent here), every run must use the recorded arguments, no recorded run may be left unmade, and a streamed run must end where the host ended it. Also replays each tag-reading fixture with `mkvTags: false`. `PROBE_FIXTURES_DIR=<dir>` replays another directory (a large fuzz run). Fixtures: 35 corpus files recorded with the real tools (`file`, `moviehash`), 90 hand-written cases (`syntheticCases()`: Dolby Vision, HDR10+, rotation, frame-rate lies, late audio, odd tags, crop retries, failures) and 150 seeded random ones (`fuzz-*`). Last run: 3 000 extra random cases (seed 2), 0 mismatches.
  - Regenerate (host repo): `PROBE_TOOLS=$(tools/probe-tools.sh) tools/gen-probe-corpus.sh` here, then `cd backend && FLIKS_ENGINE_REPO=<this repo> PROBE_CORPUS_DIR=<this repo>/probe-corpus PROBE_TOOLS=$PROBE_TOOLS npx jest test/engine-vectors/probe-vectors` (without the corpus variables the recorded corpus calls are kept and `expected` is recomputed). Verify without tools: `FLIKS_ENGINE_REPO_CHECK=<this repo> npx jest test/engine-vectors`. Bigger fuzz: `PROBE_FUZZ_SEED=2 PROBE_FUZZ_COUNT=3000 FLIKS_ENGINE_REPO=/tmp/big ...` then `PROBE_FIXTURES_DIR=/tmp/big/fixtures/probe cargo test -p fliks-engine-core --test probe_fixtures`.
- `crates/core/src/probe/tests.rs` (unit): `fixtures/probe/_titles.json` (language and forced/SDH inference of 1 142 titles), `_fps.json` (`toFixed(3)` frame-rate text of 489 doubles), `_moviehash.json` (the host's hash of sparse files up to 10 GiB next to the specified one) against the engine; `probe::{js,lang,mkv,crop}` unit tests.
- `crates/engine/tests/probe_live.rs`: `corpus_matches_the_host` (no-op unless `PROBE_CORPUS_DIR`; set `FFPROBE_PATH`, `FFMPEG_PATH`, `MKVMERGE_PATH` to the tools of `tools/probe-tools.sh`) runs the real `POST /v1/probe` on the 35 corpus files and compares `ok`, `info` (without `schemaVersion`, which the engine stamps) and `moviehash` to the fixtures; `probe_validates_the_request` (relative path 400, unreadable file `ok: false`).
- `crates/engine/src/probe/run.rs` (unit, unix): output, exit status, missing binary, timeout, output cap and early stop of the process runner with shell-script tools.
