# Protocol

Version: `protocolVersion = 1` (`GET /v1/hello`, with `features[]`). Schema: [openapi.json](openapi.json), generated from `crates/core/src/api.rs`; `crates/engine/tests/openapi_wire.rs` keeps every wire key in it.

## Transport

JSON over HTTP, SSE for events. Two planes:

1. Control (`/v1/*`): host to engine, `Authorization: Bearer $FLIKS_ENGINE_TOKEN`, loopback only.
2. Data (player to engine): `GET`/`HEAD` with Range, credential delegated to the host resolver.

The control plane is only on `--listen`. The data plane is served on `--listen` too (for a host behind its own proxy) and, with `--upstream`, on the public gateway (below).

## Rules

- Additive only within v1: never remove or rename a field, endpoint or enum value.
- Readers ignore unknown fields, and unknown variants of event and other tagged unions (new `EngineEvent` types are additive).
- No 64-bit integers in JSON (use f64, u32 or i32).
- A breaking change goes to `/v2`, served next to `/v1` for one release.
- A host declares a minimum protocol and degrades per feature above it.

## Worker protocol (engine to host)

A worker (the local engine or a remote one) pulls optimisation and verification work from the host, over HTTP it initiates, like `/engine/resolve`. Types: `crates/core/src/api/worker.rs` (`WorkerHello`, `LeasedJob`, `JobKind::Optimize`/`Verify`...), all in `openapi.json`. Bodies are JSON, camelCase. The executors (`docs/spec/jobs.md` section 11) run `Optimize` and `Verify` as jobs; a failure is `<class>: <message>`, the class being a `JobErrorClass`. The worker loop (`engine::worker`) leases and reports them; it runs only when the host's `PUT /v1/config` carries `worker: true`.

Auth: `Authorization: Bearer`. The local engine sends its `hostToken`; a remote worker sends its own token (issued by the host, stored hashed, revocable), which is only valid on `/engine/workers/*` and `/engine/jobs/*` and only for the leases it holds. `workerId` is the `instanceId` of the worker's `hello`.

| Route | Body -> answer |
|---|---|
| `POST /engine/workers/hello` | `WorkerHello` (`instanceId` generated at startup, `engineVersion`, `devices: [{ id, name?, encoders, decoders, maxJobs, pause: suspend\|restart }]`, `jobs: [{ id, attempt }]` still held) -> `WorkerHelloResponse` (`settings`: `leaseS` 60, `heartbeatS` 15, `longPollS` 30, `uploadChunkBytes` 8 MiB, optional `cpuWeight` (software optimization weight, default 2) and `gpuPlaybackBeforePause` (hardware reads that pause a device's GPU jobs, default 1, 0 never), `deviceGpuPlaybackBeforePause` (the same per device id); `abandon`: job ids to drop). Every other lease of the instance is put back in the queue at once. Path access and mappings are set by the host's admin, never declared by the worker. |
| `POST /engine/jobs/lease` | `LeaseRequest { workerId, deviceId }` -> `LeasedJob` or `204`. Long-poll: the host holds the call up to `longPollS`, answering `204` when nothing fits the device. `LeasedJob`: `id`, `attempt` (fencing, +1 per lease), `leaseS`, `kind` (`Optimize { payload }` or `Verify { payload }`), and either `inputPath` + `stagedPath` (shared filesystem) or `inputUrl` + `inputToken` (remote read). A response lost in transit costs no retry: only real failures count against the host's `maxFailures`. |
| `POST /engine/jobs/{id}/heartbeat` | `JobHeartbeatRequest { workerId, attempt, progress, paused }` every `heartbeatS` -> `JobHeartbeatResponse { leaseUntil, cancel }`. |
| `PUT /engine/jobs/{id}/output` | Remote workers only. Body: one raw chunk of the staged file (`uploadChunkBytes`). Headers: `Upload-Offset` (offset of the chunk, must equal the bytes the host holds, else `409` with `UploadAck.receivedBytes` to resume from), `Upload-Complete: ?1` on the last chunk, `X-Fliks-Attempt`, `X-Fliks-Worker-Id`. One upload per job at a time; the host hashes the stream as it receives it -> `UploadAck { receivedBytes }`. |
| `POST /engine/jobs/{id}/result` | `JobResultRequest { workerId, attempt, ok, outSize, outSha256?, outInfo?, error?: { class, message, stderrTail? } }`. The host compares `outSize` and `outSha256` with what it received (remote) or read at `stagedPath`. |

Worker loop: the engine declares a `cpu` device (`libx265`, `libsvtav1`; `maxJobs` = slots / 2) and one `gpuN` device (`maxJobs` 1, `name` = the card's label) per detected GPU, `gpu0..gpuN`. `pause` is `restart` where ffmpeg cannot be suspended (no pause capability, or `FLIKS_OPTIMIZE_PAUSE=restart` for a GPU short of VRAM), else `suspend`. It leases only for a device with room, heartbeats every `heartbeatS` with `paused: true` while playback holds every run of the job, and answers a lease `404 unknown worker` (host restart) with a new `hello` listing the leases still held. A job stopped to yield (`pause: restart`) ends with `busy`: the host requeues it without counting a failure. The lease's `stagedPath` becomes `OptimizePayload.stagedPath`; an executor failure `<class>: <message>` becomes `JobResultRequest.error`.

Fencing: `409` on `heartbeat`, `output` and `result` means only that `attempt` or `workerId` no longer match the lease (expired and re-leased, cancelled, abandoned). The worker kills its encoder and deletes its files. A network error or `5xx` kills nothing: the worker retries until its own lease expires locally (`leaseS` after the last answered heartbeat).

Remote source: `inputUrl` is the main engine's data plane (`purpose: download`) with `inputToken` bound to the file; the worker sends it as a header (`ffmpeg -headers`) with `-reconnect 1 -reconnect_on_network_error 1`; a read that still fails ends with class `network`. Only the `remux` and `reencode` levels read remotely; the output is staged in the engine's cache, then uploaded with `PUT /engine/jobs/{id}/output` in `uploadChunkBytes` chunks (a `409` carries `UploadAck.receivedBytes`, the upload continues from it; no ack means fenced) before the result is posted, and the staged file is removed. Heartbeats go on during the upload.

Remote worker mode: `fliks-engine --worker-url http://host:port` (or `FLIKS_WORKER_URL`) with `FLIKS_WORKER_TOKEN` makes the engine a worker of that host without `PUT /v1/config`. It has no library access, so it only runs leases carrying `inputUrl`. Staged outputs live in `<cache>/optimize/` and are removed at startup. A worker outside the LAN must use an `https://` URL (the platform's root certificates; `SSL_CERT_FILE` overrides): the bearer token and every uploaded output travel in it. Behind nginx, raise `client_max_body_size` above `uploadChunkBytes` (default 1 MiB would answer every chunk `413`). Docker: the engine image with those two variables and a volume on `FLIKS_TRANSCODE_DIR`. Windows: run the released `fliks-engine.exe` with the two variables as a service (e.g. NSSM, `nssm set <svc> AppEnvironmentExtra FLIKS_WORKER_URL=… FLIKS_WORKER_TOKEN=…`), `FLIKS_TRANSCODE_DIR` on a drive with room. macOS: a launchd agent (`~/Library/LaunchAgents/*.plist`, `EnvironmentVariables` with the same variables, `KeepAlive` true, `RunAtLoad` true), loaded with `launchctl bootstrap gui/$UID`. The host's resolver answer is cached for `min(60 s, remaining lease)` and the host calls `POST /v1/revoke { credential }` on every `409` or requeue.

Error classes (`JobErrorClass`): `access` (a path is unreadable or unwritable), `io` (read or write failed mid-job), `corrupt` (the source cannot be decoded), `damaged` (the output failed its own check), `nospace` (no room to stage), `engine` (encoder crash), `network` (transfer failed), `verify` (a `Verify` job found the file faulty), `busy` (device or file in use, goes back without counting as a failure), `stale` (the source no longer matches the queue-time snapshot).

## Resolver (implemented by the host)

```
POST {hostUrl}/engine/resolve   Authorization: Bearer {hostToken}   (401 on a wrong token)
  <- { mediaId, credential, purpose: stream|download|sprite|subtitle|live, subtitleId?, streamIndex? }
  -> { allow: bool, path?, parts?, ownerId?, format?, ttlS? }
```

- `hostUrl`/`hostToken` come from `PUT /v1/config`. Types: `ResolveRequest`/`ResolveResponse` in `openapi.json`.
- `credential`: the client credential exactly as received, one string, in the host's own extractor order: the `Cookie` header value, else a `Bearer` `Authorization` value (`Bearer <jwt>`), else the `?token=` value, else a `Basic` `Authorization` value (`Basic <base64>`). The host parses all four; a request with any cookie sends the cookie header.
- Device credentials (additive, `hello.features` lists `device-credentials`): clients that cannot do a host login (e-readers, OPDS and sync apps) present an opaque credential the host issued, as `Authorization: Basic`, as `?token=`, or in the path as `/cred/<token>/api/stream/<id>/...`.
  - The path form is the same data-plane route with that token as its `?token=` (a `token` already in the query is replaced, percent-encoding is undone). `GET`/`HEAD` only (405 otherwise) and only `api/stream/<numeric id>...`: any other tail, `info/*` and `livetv` included, is a 404, and `edl` is a 404 too. HLS playlists name their URIs with `?token=`, never with the path form.
  - Order: a path token wins over everything (an e-reader sends its own `Bearer` on every request); then any cookie, a `Bearer`, a `?token=`, and `Basic` last.
  - `ResolveRequest.credentialSource` (`cookie|bearer|query|path|basic`, absent without a credential) tells the host where the engine found it, so it can refuse a password-like value that travelled in a URL. It is set by the engine only (a client cannot forge it) and is not part of the cache key.
  - The credential is capped at 8 KiB: longer is a 400 without a resolver call.
  - A device credential is opaque to the engine: the host validates it and its scope, and answers `allow`/`ownerId` as for any user. For `stream` and `download` an item answers `parts`, so `/api/stream/{id}/parts/{n}` works with one.
  - Host duties: issue high-entropy credentials, never a user password. Keep their `ttlS` short, since answers (denials too) are cached per credential. The engine sends no client address, so the host cannot throttle guessing per client from the resolver.
  - Revocation: `POST /v1/revoke { credential }` (the credential as the host received it, any form) purges its cached answers, grants and denials, and touches no session; alone it is a complete request, with `ownerId` or `mediaFileIds` the usual revoke runs too.
- `mediaId`: the media file id (number); for `live` the live viewer's `sessionId` (string).
- `live` (M6): every data-plane request of a live sid; the host checks the channel is still playable for that user (its `assertStillPlayable`) and answers `{ allow, ownerId, ttlS }` without a path. A denial that names the viewer's owner (`{ allow: false, ownerId }`) ends the viewer (`SessionEnded { reason: revoked }`); any other denial (no `ownerId`, another user's) is a 403 and leaves it; an `ownerId` other than the viewer's on a grant is a 403. `ttlS: 0` re-checks every request, as the host did on every playlist poll.
- `stream`/`download`: `path` = the media file, `format` = its MIME type (optional, else the engine guesses from the extension). An item answers `parts` (additive) in place of `path`: `{ path, durationS?, startS?, endS?, format? }[]` in playing order, read by `GET /api/stream/{id}/parts/{n}` (byte range of part `n`, 404 past the last). A single `path` stays valid; the order must match the open request's `parts`. The sessions of an item carry their own parts from the open request, so the resolver only gates the HLS routes.
- `sprite`: `path` = `sprite.jpg` (its `sprite.json` is the sibling), not checked by the host, and optional since M5: the engine serves its own sprite (`Sprite` job) first, then this path, else 404.
- `subtitle`: `subtitleId` (external file: `path` = the file, `format` = its extension `srt`/`ass`/`vtt`) or `streamIndex` (embedded: `format: "embedded"`, `path` = the media file, the engine extracts the stream).
- Denials are `{ allow: false, ttlS: 60 }` without a path (`ownerId` too on a `live` denial for a known user). A host error is an HTTP 5xx and is never cached as a denial.

The engine knows neither JWT nor ACL, nor what a device credential is. Answers (denials included) are cached per `(hash(credential), mediaId, purpose, subtitleId, streamIndex)` for `ttlS` (60 s default). Host unreachable, timing out (5 s) or failing: an expired grant and the sessions of the requested file keep being served, other requests get 503 + `Retry-After: 2`. Data-plane answers: 403 on a denial; on a `?sid=` the engine no longer knows, 410 `{ code: "session_expired", sid, message }`; on a session of another owner or file, 403. `POST /v1/revoke` kills sessions and purges the cache immediately (`credential` purges one credential's answers only, see above). A repeated bad credential costs the host one call per `ttlS`. An expired denial is dropped at once (a grant keeps its stale grace), and a full cache sweeps to 90%, denials before grants, so a flood of distinct bad credentials cannot evict a valid grant. The engine does not rate-limit and sends no client address: throttling guessed credentials is the host's, on the denials it answers. Credentials are never logged: the engine keeps no access log, a `ResolveRequest`'s `Debug` redacts `credential`, and every other log line names hosts and files only.

## Data plane routing (host prefix `/api/stream`, M3 implemented)

Engine serves `GET`/`HEAD` of `/api/stream/:mediaFileId/**` except `edl`; everything else is forwarded to the host. `GET`/`HEAD` of `/cred/:credential/api/stream/:mediaFileId/**` is the same data plane with a path credential (above). Everything the engine does not serve, `Authorization` (Basic included) and path tokens too, reaches the host verbatim: only hop-by-hop headers (`Proxy-Authorization` among them) are stripped.

| Engine | Host |
|---|---|
| `:id` (direct play, `?download=1`) | `POST :id/playback-info`, `DELETE sessions/:sid`, other non-GET |
| `:id/master.m3u8`, `:id/:quality/index.m3u8`, `:id/:quality/:segment` | `info/*` (via `/v1/estimate-sizes`, `/v1/capabilities`) |
| `:id/audio/:idx/index.m3u8`, `:id/audio/:idx/:segment` | `:id/edl` |
| `:id/item/index.m3u8`, `:id/item/:file` (init or global segment of an item), `:id/parts/:n` (byte range) | |
| `:id/iframe/index.m3u8`, `:id/iframe/:segment` | companions/download, `subtitles/*` and subtitle search |
| `:id/thumbnails/sprite.{json,jpg}` | |
| `:id/subtitles/embedded/:idx[/download\|/index.m3u8]`, `:id/subtitles/:subId[/download\|/index.m3u8]` | |
| `/api/livetv/sessions/:sid/{index.m3u8,direct.ts,:segment}` (M6, `GET`/`HEAD`) | `/api/livetv/*` otherwise (`DELETE sessions/:sid`, `PUT sessions/:sid/state`, `channels/:id/play`) |

Direct play and `parts/:n` answer with `ETag: "<size>-<mtimeMs>"` and honour `If-Range`: a ranged read that resumes after the file was replaced (a library optimization swaps it) gets the whole new file with `200`, never the rest of a different one.

A fMP4 run that exits cleanly without a sample in its first segment (ffmpeg seeked past the end of the source, e.g. a truncated file) is a failed run: `JobEnded { state: Failed, exitCode: 0, reason: "no-media" }`, logged once at warn with the file and start position, its cache files removed, and the segment request answers `404`, like a segment past the playlist's last one. A sample-less segment is never served.

DirectStream: `:id/remux/*` and a remux session's audio renditions come from copy-video runs on the keyframe grid frozen at open (`docs/spec/runtime.md` section 9).

## Gateway (`--upstream`, spec: `docs/spec/gateway.md`)

`fliks-engine --upstream http://host:port [--engine-upstream http://engine:port] [--public-listen 0.0.0.0:4848] [--gateway-routes routes.json] [--supervise -- cmd]`

- The public listener serves the engine routes of a configurable route table (ordered `{ target: engine|forward, methods?, path }` rules, `:name`/`*` one segment, trailing `**`; default = the table above) and forwards everything else to the upstream verbatim: method, path+query, headers (plus `X-Forwarded-For/Proto/Host`, minus hop-by-hop), streamed bodies, SSE, WebSocket/`Upgrade`. Upstream unreachable: `502` on forwarded routes, engine routes unaffected. With `--engine-upstream`, the `engine` rows are forwarded to that URL instead of a local data plane; this process does not transcode.
- `/v1/*` of the engine is never on the public listener; it stays on `--listen`. A `/v1/*` path there is just another forwarded path.
- `--supervise --upstream`: the host is started with `PORT=<upstream port>` (plus `FLIKS_ENGINE_URL`/`FLIKS_ENGINE_TOKEN`) so it listens on the internal address. Without `--supervise` the host is any process reachable at the URL (remote host, gateway-only role); without `--upstream` nothing changes.
